# Semantic TextNavigator — Contract Checker

Локальный прототип для специалиста по закупкам: показывает действующие сумму и срок поставки, связывает документы и позволяет проверить каждое значение по исходному абзацу.

## Запуск

Требуются Python 3.10+ и (для чата) локальная Ollama.

~~~powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# В отдельном терминале Ollama:
ollama pull qwen2.5:7b

# Запуск:
$env:OLLAMA_HOST="http://127.0.0.1:11500"
$env:OLLAMA_MODEL="qwen2.5:7b"
streamlit run app.py
~~~

По умолчанию используется демонстрационный набор в documents/. Можно загрузить собственные TXT: тип документа и номер договора определяются по содержимому, а не по имени файла. Без Ollama доступны обзор, источники и четыре быстрые проверки; чат требует локальную модель.

## Пользователь и сценарий

Основной пользователь — специалист по закупкам, которому нужно быстро сверить сумму и срок поставки по комплекту договорных документов. Загрузить TXT → проверить итоговую таблицу → раскрыть источник → задать вопрос в чате. LLM выбирает инструменты, но факты получает только из них.

## Архитектура

Streamlit Chat → Local Agent Runtime → Ollama /api/chat (tool calling) → allowlisted Python Tools → Domain Workflows → Evidence + Contract Snapshot.

Обработка документа: ingestion/normalization → classification → extraction → evidence. Resolver применяет версионируемые правила из config/rules.json. LLM не определяет юридическую применимость изменений. MCP/Hermes, vector DB и платные API не требуются.

## Ключевые решения и компромиссы

1. **Детерминированный resolver.** Подписанное обеими сторонами допсоглашение применяется только при известных датах подписания и вступления в силу, если обе даты не позже даты проверки. Проекты и письма показываются отдельно. Компромисс: неизвестный или сложный юридический статус требует ручной проверки.
2. **Evidence-first.** Каждое найденное поле несёт файл, цитату, номер абзаца и anchor. Компромисс: точность зависит от формулировок TXT; неизвестные шаблоны требуют расширения extractor.
3. **Собственный ограниченный agent runtime.** Ollama выбирает один из пяти allowlisted tools; максимум пять шагов на вопрос. Компромисс: качество tool calling зависит от выбранной модели. Чат не считается источником фактов без вызова инструмента.

## Допущения и границы

- Дата проверки по умолчанию — 10.03.2026, её можно изменить в интерфейсе.
- Подписание подтверждается явным маркером «подписано обеими сторонами»; дата вступления в силу извлекается отдельно.
- Стоимость извлекается только из контекста общей стоимости; аванс и внутренний бюджетный лимит не считаются ценой договора.
- Поддерживаются TXT и формулировки учебного набора. OCR, PDF/DOCX, электронная подпись, юридическая экспертиза и произвольные корпоративные регламенты не реализованы.
- Это демонстрационный прототип, не юридическое заключение.

## Метрики качества

- **Field Exact Match:** доля точно извлечённых значений суммы и срока относительно размеченного набора.
- **Evidence Coverage:** доля найденных значений с корректной цитатой и ссылкой на исходный абзац. Целевой показатель для отображаемых значений — 100%; фактические показатели нужно получить тестированием.

## Масштабирование до 100 000 документов и ACL

Добавить объектное хранилище оригиналов, PostgreSQL для метаданных/версий/состояний, очередь и независимые workers для обработки, полнотекстовый и при необходимости векторный retrieval. Права доступа проверять до поиска и выдачи фрагментов, а также повторно при формировании ответа. Логи tool calls и решений хранить с tenant/user scope. Kafka/Spark вводить только при подтверждённой потоковой нагрузке и объёмах.

## Отчёт о вайбкодинге

- Инструмент: ChatGPT (проектирование, генерация и ревью кода) + GitHub.
- Характерные запросы: «Раздели извлечение фактов и разрешение действующих условий»; «Добавь ограниченный Ollama tool-calling loop с allowlist»; «Проверь кейсы отсутствующей суммы, письма и неподписанного проекта».
- Типичный риск кодогенерации: regex может принять дату оплаты за срок поставки или бюджетный лимит за сумму договора. Проверка: отдельные pytest-кейсы для аванса, оплаты, лимита, письма и отсутствующей суммы.
- Фактическое время и оставшиеся задачи: заполнить после контрольного прогона по лимиту задания в 4 часа. Не считать плановое время фактически затраченным.
